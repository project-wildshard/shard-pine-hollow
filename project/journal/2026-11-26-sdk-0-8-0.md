# SDK 0.8.0, and the Blender targets name the SDK's lib (opus-blend132, meta QA 11-25 row 132)

- `pnpm dlx @wildshard/cli upgrade 0.8.0`: the SDK, cli, dev, kit, build and upload at 0.8.0, format 0.80.0 (engine
  0.1.96). Pine Hollow's weapons dropped `legacySlot` on 11-24, so the migration had no manual step. The hero
  re-stamped its content hash; the curated art is unchanged.
- `scripts/blender/targets.json` named the SDK's lib by monorepo paths (`scripts/blender/lib/export-scene.mjs`,
  `glb.py`). The area export's `pre` runs `$SDK/scripts/blender/lib/export-scene.mjs` (build.sh expands `$SDK`), and
  the file lists name the SDK's files by their installed path, `node_modules/@wildshard/sdk/...`.
- `build_trees.py` climbed five folders to the monorepo's `scripts/blender/lib/` for `glb.py`, and for its repo root.
  It reads `glb.py` from `$SDK` (build.sh exports it), else the installed SDK, and its repo root is three folders up.
- The manifest still sits at `scripts/blender/`: the installed engine 0.1.96 lint finds the registered Blender helpers
  only there. Its move to `src/blender/` waits on an SDK publish that pins an engine with `6488b9233` (v0.1.97).
